## Task outlines

### M0: Scaffold & spikes (detailed plan exists)
1. Workspace scaffold and toolchain (pnpm workspaces, strict TS, build, vitest, package skeletons)
2. Guardrails and CI (ESLint import boundaries, `Math.random` ban, GitHub Actions on Linux and Windows)
3. Spike R1: paper.js headless (booleans, `smooth`, `simplify`, plain-cubic round trip; S6 evidence)
4. Spike R2: resvg-js text (Latin and Arabic, bundled fonts, `textPath`, `getBBox` vs opentype; S2 evidence)
5. Spike R3/R4: MCP SDK v2 stdio server (image block, prompt, instructions, schema probe; S1 evidence)
6. Client verification and spike report (Claude Desktop plus one more client; write outcomes into spec S1–S7)

### M1: Geometry module (`engine/src/geometry`)
1. `bezier.ts`: eval, derivative, normal, exact bounds, Gauss–Legendre arc length, LUT and inverse
2. `transform.ts`: `Mat6` compose, invert, pivot rotation, decompose, apply to segments
3. `flatten.ts`: Wang flattening, winding number (nonzero and even-odd), signed area
4. `paths.ts` part 1: quadratic→cubic, arc→cubic, centripetal Catmull–Rom
5. `paths.ts` part 2: corner rounding (fillet clamping)
6. `paper-adapter.ts`: scope lifecycle, plain ⇄ paper conversion, `simplify` fitting
7. `boolean.ts`: the four booleans, epsilon handling, boolean regression suite

### M2: Scene model, registry, transactions, SVG out
1. `scene/model.ts`: types (A3), Zod document schema, `createDocument`
2. `scene/query.ts`: world transforms and exact world bounds, memoized via `WeakMap`
3. `scene/store.ts`: immer transactions, rollback, checkpoints
4. `ops/registry.ts`: `defineOp`, catalog, `{code,message,hint}` errors, units/percent, `$last`, batch executor (decide S5 here)
5. `render/svg.ts`: scene → SVG serializer with live token resolution
6. Initial ops (rect, ellipse, polygon, line, style, group, delete) and the determinism test

### M3: First end-to-end MCP slice
1. `render/raster.ts`: resvg PNG, overlays (ids, bounds, grid), region crop
2. `render/export.ts`: SVGO, precision, token inlining, id strip option
3. `mcp-server` runtime: `SessionStore`, limits, timeouts (decide S7), pino to stderr
4. Tools `create_document`, `apply_ops` (S1 outcome), `render` (+ disk fallback), `export_svg`
5. `npx` entry, client config docs, acceptance in a real client

### M4: Paths, booleans, transforms, layout
1. Path ops: `path_from_points` (polyline, smooth, fit), `path_commands`, `round_corners`, star
2. Boolean ops
3. Transform ops with anchor or point pivots
4. Layout ops: `place`, `align`, `distribute`
5. `snap` and the rbush candidate index (`analysis/spatial-index.ts`)
6. Structure ops: reorder, clip, mask, duplicate, rename, ungroup

### M5: Style & color
1. culori palette (harmonies, ramps, gamut mapping) and tokens ops
2. Linear and radial gradients interpolated in OKLab (5–9 stops)
3. Filters (drop shadow, blur), opacity, blend modes; contrast utility

### M6: Generators
1. `random/rng.ts`: per-node derived alea plus simplex noise
2. `blob` and `wave`
3. `scatter`: Poisson-disk inside a shape, density gradient
4. `repeat_along_path`, `array_grid`, `array_radial`
5. `roughen` and performance caps at maximum counts

### M7: Analysis & history
1. `describe_scene` (detail levels)
2. `measure`
3. `lint` geometric checks (off-canvas, overlap, near-miss alignment, degenerate, tiny)
4. `lint` text contrast sampled from the render; incremental warnings in `apply_ops`
5. `history` and `document_io` tools

### M8: Text
1. `text` node, SVG emission, bundled fonts, font registration with resvg
2. Text measurement (S2 outcome)
3. `text_on_path`
4. Arabic support status written into `guide`

### M9: Agent kit & prompt delivery
1. Core contract, workflow guide, server instructions
2. Op catalog generated from the registry; `guide(topic)` tool
3. Style presets (flat, line-art, isometric-lite) and the text-only overlay
4. MCP prompt `/illustrate`
5. CI check that every op referenced in agent-kit exists in the registry

### M10: Evaluation & hardening (per spec A2)
1. CI render-regression fixtures (op scripts → PNG → pixelmatch baselines)
2. Dev-only eval harness (MCP client plus OpenAI-compatible tool loop)
3. About 20 briefs and the raw-SVG baseline runner
4. Side-by-side HTML report and scoring rubric
5. Runs on 2 or more model families; error-hint improvements from transcripts
6. README (install, client setup, tool reference, limits, known limitations)
